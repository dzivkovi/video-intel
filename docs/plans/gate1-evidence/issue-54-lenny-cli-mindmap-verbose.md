## AI Product Building Principles

*   **Token Management**
    *   Give engineers unlimited tokens initially to foster experimentation and "crazy ideas" (25:54, 26:49)
    *   Optimize and cost-cut token usage only after an idea has proven successful (26:30, 27:08)
*   **Model Interaction**
    *   Don't try to "box the model in" with strict workflows or excessive scaffolding (1:12:13)
    *   Give the model tools and a goal, then let it figure out the solution (1:12:30)
    *   Avoid giving too much upfront context; provide tools for the model to get context itself (1:12:40)
    *   Embrace "The Bitter Lesson": always bet on the more general model over specific or fine-tuned ones (1:12:50)
    *   Scaffolding gains (10-20%) are often wiped out by the next model version (1:13:50)
*   **Future-Oriented Development**
    *   Assume future models will be better at using tools/computers and running for longer periods unattended (1:16:01)
    *   Building for future models may lead to poor product-market fit initially but allows hitting the ground running later (1:14:10)
*   **User Tips for Claude Code/Cowork**
    *   Use the most capable model (e.g., Opus 4.6 with maximum effort) for efficiency and cost-effectiveness (1:17:40)
    *   Utilize "plan mode" for 80% of tasks to let the model outline steps before execution (1:18:20)
    *   Experiment with different interfaces (terminal, desktop app, mobile app, Slack) to find what works best (1:19:00)
