## Agentic Development Workflow

*   **Methodology**
    *   Prefers "agentic engineering" over "vibe coding" (0:31)
    *   Practices "agentic engineering," occasionally "vibe coding" with regrets (1:05:03)
    *   Refers to "agentic trap" where people overcomplicate prompts (1:04:45)
    *   Considers "vibe coding" a slur (1:04:45)
    *   Don't force worldview on agents; let them leverage their training (1:11:20)
    *   Working with agents requires acceptance, like leading an engineering team (1:11:39)
    *   Design codebase for agent navigability, not personal perfection (1:11:39)
    *   Don't fight agent-chosen names, as they are based on training weights (1:11:39)
    *   Requires "letting go" and accepting agent's choices (1:13:15)
    *   Never reverts code; commits directly to main (1:13:31)
    *   If problems arise, asks agent to fix them (1:13:31)
    *   Doesn't refer to past sessions (YOLO component) (1:13:31)
    *   Avoids rolling back; moves forward and fixes issues (1:13:57)
    *   Uses local CI (DHH inspired), pushes to main if local tests pass (1:13:57)
    *   No `develop` branch; `main` is always shippable (1:13:57)
    *   Building and playing are key to developing LLM interaction skills (1:19:47)
    *   Against fully automating agentic workflows with orchestrators (e.g., Gaston) (1:19:47)
    *   Ideas evolve through iterative building and playing, not upfront planning (1:19:47)
    *   Full automation misses "style, love, that human touch" (1:19:47)
    *   Asks agents "what can we refactor?" after building features (1:46:25)
    *   Agents help identify pain points and suggest improvements (1:46:25)
    *   Uses agents to write tests and documentation (1:46:25)
