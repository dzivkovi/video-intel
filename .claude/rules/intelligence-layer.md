# Intelligence-layer standalone utilities

Moved verbatim out of the root `CLAUDE.md` so these guardrails load when you touch the analytics scripts instead of in every session. Same content, same authority: the "Reviewers:" clauses below are binding.

**Standalone utility:** `scripts/intel_graph.py` - the weak-signal / commonality-detection layer (issue #85, R&D). Loads existing corpus artifacts (meta.json, transcripts via `chunk_transcript`, concepts.json, taxonomy.json) into a DuckDB truth store shaped as the 6-node / 6-edge starter schema (`~/.cache/video-intel/intel.duckdb` by default: local disk per the ADR-0016 precedent), projects a disposable entity co-occurrence graph into Neo4j (`VI_`-prefixed labels only), runs community detection + PageRank via GDS (seeded Leiden by default for reproducibility; GDS Louvain has no randomSeed and varies run-to-run, kept behind `--algo louvain`; `--gamma` tunes Leiden resolution), writes the results back into DuckDB, and verifies the issue #85 acceptance gate (`load` / `project` / `verify` subcommands). Environment setup: `docs/intelligence-layer-environment-setup.md`; install via `pip install -e ".[intelligence]"`. Three invariants reviewers must protect: (1) **DuckDB is truth, the Neo4j graph is regenerable** - never make the graph the source of anything; (2) **anti-circularity** - the community-detection input graph is built only from shared-artifact co-occurrence between surface terms; `taxonomy.json` / `concept_id` normalization must never contribute edges (it is the answer key the alias-recovery gate is scored against, so an edge from it makes the gate a tautology); (3) **provenance presentability** - `verify` may only surface claims that have an `expresses` row (verbatim quote + segment + timestamp). It only READS corpus artifacts and never writes to the corpus, config, or meta.json. Test contract: `tests/test_intel_graph.py`.

**Standalone utility:** `scripts/lead_lag_report.py` - the coverage-corrected lead-lag report (issue #93, first analysis off the DuckDB truth store). Read-only against `intel.duckdb`; answers "who covers a concept first, who follows" with two corrections that ARE the contract: (1) **eligibility gate** - a concept only scores when >= `--min-eligible` adopters had coverage windows active at its emergence, so deep-backfill channels cannot fake precedence; (2) **rate normalization** - expected firsts are proportional to posting rate among eligible adopters, `lift = observed / expected`. The rendered report must keep the naive-vs-corrected tables and the kill-criterion Spearman diagnostics (lift vs coverage-start, lift vs corpus size) - they are how issue #93's kill criterion stays checkable. One report script, not a framework (issue #95 guardrail); do not grow it into a general analytics module - the failure mode is analytics scaffolding accreting before any finding has proven the method worth it, which two independent reviews flagged as the highest-regret mistake. Test contract: `tests/test_lead_lag_report.py` (`test_backfill_first_before_anyone_covered_concept_skipped` locks the eligibility gate). Generated reports land in `docs/reports/`. Sibling renderer: `scripts/lead_lag_viz.py` (issue #94) emits the same statistics as ONE self-contained interactive HTML (inline CSS/JS, no external CDNs; the only outbound links are YouTube evidence deep links). It renders, never recomputes - `build_viz_payload` mirrors `render_report`'s selection logic. Two rendering invariants reviewers must protect: (1) the ranking view groups creators into evidence tiers (robust / mid / small-sample) so the top visual slot always goes to a robust row - a small-sample lift must never occupy the top-of-chart position (Codex gate constraint on PR #96 plus the Gate 1.5 fresh-eye finding that badges alone do not fix visual hierarchy); (2) the page must stay fully self-contained - no CDN scripts, fonts, or stylesheets. Test contract: `tests/test_lead_lag_viz.py` (`test_ranking_is_tiered_by_evidence`, `test_no_external_resources`). **Print support (issue #101):** everything print-specific lives inside `@media print` plus `.print-only` blocks (hidden on screen), so print can never alter the reviewed screen design - the interactive timeline is replaced in print by a `#printchains` section that expands ALL chains sequentially with visible evidence URLs (print has no interactivity). `--pdf <path>` (requires `--out`) drives headless Chromium print-to-PDF via a lazy `playwright` import with an actionable install message. Reviewers: any print rule outside the `@media print`/`.print-only` scope, or a change that drops the all-chains print expansion, regresses the #101 contract - `tests/test_lead_lag_viz.py::TestPrintSupport` locks it. Personal copies of generated reports conventionally land in `<output_dir>/_reports/` (the analytics sibling of `_briefings/`); the corpus knows nothing about them.

**Standalone utility:** `scripts/burst_report.py` - Kleinberg concept-burst detection (issue #103, method 4 of #95). Read-only over `intel.duckdb`; runs the two-state Kleinberg automaton (KDD 2002) on each concept's distinct-video mention stream and reports bursts with a start date, intensity, and rising/cooled status - "just caught fire" against the concept's OWN baseline, the principled upgrade of PR #62's fixed-window `spike_ratio`. Two rendering invariants reviewers must protect: (1) the **corpus volume context table renders before any burst listing** - every stream rides the corpus's indexing volume, so a scan surge makes many concepts "burst" simultaneously; removing the table turns corpus growth into fake topic fire (the 2026-07-12 real run: 50 of 95 bursts "rising" while monthly volume grew 31 -> 202); (2) every listed burst carries its **"first in burst" evidence link** and the "lead for inspection, not a verdict" caveat (corpus is ~100x smaller than the literature's). One report script, not a framework (#95 guardrail); no Gemini calls; the briefings hook (#84) is deliberately NOT wired - it stays a follow-up so briefings code paths keep their own review surface. Test contract: `tests/test_burst_report.py` (`test_uniform_stream_yields_no_burst`, `test_report_shows_corpus_volume_confounder_table`).

**Standalone utility:** `scripts/sdsm_network.py` - the SDSM-validated creator-creator network (issue #98, method 2 of #95). Read-only over `intel.duckdb`; builds the bipartite creator-concept 0/1 adoption matrix (the exact adopter definition reused from `lead_lag_report.load_first_mentions` - a dated `has_concept` row), fits a degree-preserving null, and keeps only creator pairs sharing significantly more concepts than that null expects (Benjamini-Hochberg, q<0.05). stdlib + numpy, no stats framework (#95 guardrail). Three invariants reviewers must protect: (1) **the primary null is the exact-margin BiCM** (`fit_bicm`, per-node degree effects `sigmoid(a_i+b_j)`) which reproduces BOTH row and column margins - the whole point of SDSM over the plain hypergeometric is to condition on creator prolificness AND concept popularity; Neal's 2-predictor logit (`fit_logit_degrees`) is a SENSITIVITY comparison only because it misfits row margins (~55 concepts on the real corpus) and under-conditions. Do NOT make the logit the headline. Test contract: `test_fit_reproduces_both_margins`. (2) **The pre-registered acceptance gate lives in `classify_gate`** (pass < 40 edges / stop > half of all pairs / pass-flag between) so the ship/stop decision is testable, not prose - the 2026-07-13 real run PASSED clean at 10 edges / 465 pairs (hypergeometric baseline 314, logit sensitivity 106), with the pre-registered sensible ties (benai92-simonscrapes, mark_kashef-ramjad) surviving at the top. Either outcome (network shipped, or "corpus too homogeneous" finding shipped) resolves #98. (3) **The report keeps the hypergeometric-baseline count and the honesty caveat** (corpus ~100x smaller than the studies; edges are undirected co-adoption, not influence - "who leads whom" is `lead_lag_report`). Generated reports land in `docs/reports/`. Test contract: `tests/test_sdsm_network.py` (`test_glued_niche_pair_is_the_strongest_edge`, `test_universal_overlap_is_pruned`, `TestGate`). Companion Spec A.2 lives in `lead_lag_report.py`: `firsts_significance` adds the `p (perm)` column to the corrected ranking - the exact Poisson-binomial tail (closed-form substitute for the 10,000-draw permutation) of "is this creator's firsts count beyond rate-implied luck", BH-corrected, with a caveat that a small-sample creator can clear the rate-null and still be a coverage artifact. It touches ONLY the added column + caveat + a `win_probs` field on `CreatorStats`; the #96 guardrails (naive-vs-corrected tables, Spearman diagnostics, `ranked_creators`/`finding_chains` helpers) stay untouched. Test contract: `tests/test_lead_lag_report.py::TestPermutationSignificance`.

**Standalone utility:** `scripts/disparity_backbone.py` - the PMI + disparity-filter backbone kill diagnostic (issue #99, method 3 of #95). A BOUNDED ONE-SHOT DIAGNOSTIC, explicitly NOT a framework - read-only over `co_occurs`, pure stdlib (hand-rolled Brandes betweenness; no numpy), NO new dependency and NO community-detection library (the anti-overbuild guard is the whole point). Answers ONE pre-registered question with ONE number: on a Serrano-Boguna-Vespignani disparity backbone, does betweenness reroute away from popularity, or does the top-15-betweenness set still equal the top-15-weighted-degree set? Gate in `classify_kill`: overlap >= 10 -> kill HOLDS (terms-as-nodes analytics stays retired); <= 6 -> REOPEN; 7-9 -> inconclusive. **2026-07-13 real run = INCONCLUSIVE (parked, #99 stays OPEN):** two backbones, both reported honestly - the literal PMI-weighted disparity (Spec B) is DEGENERATE (0 backbone edges at alpha=0.05; PMI log-compresses each node's incident weights so no edge dominates - PMI and the disparity filter work at cross-purposes, min disparity p=0.055), and the canonical raw-weight Serrano disparity gives overlap **9/15** (robust across alpha 0.01/0.05 and unweighted betweenness; a weighted-betweenness variant touches 10, which is why 9 is called inconclusive not kill-holds). Reviewers: keep BOTH backbones reported (the PMI degeneracy is part of the finding, not a bug to hide); the overlap is the entire deliverable - do NOT grow this into a co-occurrence analytics module or add Leiden/community detection (that is method 5's trigger, not shipped). Test contract: `tests/test_disparity_backbone.py` (`test_uniform_node_keeps_nothing` locks the degeneracy mechanism, `test_classify_kill_bands` locks the gate). Verdict note lands in `docs/reports/`.

**Standalone utility:** `scripts/wiki_atlas.py` - the Lead-Lag Creator Atlas generator (issue #105). Emits an Obsidian-readable wiki slice (creator dossiers, chain-concept pages, index.md MOC, log.md) into `<output_dir>/_wiki/`, generated from the shipped lead-lag data. It renders via `lead_lag_report.build_report_data` / `ranked_creators` / `finding_chains` and never recomputes; tier thresholds are imported from `lead_lag_viz` so the three surfaces cannot drift. The script emits DATA skeletons with `> [!todo] PROSE` / `TODO-PROSE` slots; the executing agent writes the synthesized prose into the emitted pages (the LLM-evidence-wiki pattern from `docs/brainstorms/2026-07-12-kb-browsing-surface-research.md`). Non-dull checklist invariants reviewers must protect: (1) **wikilinks only where a validated lead-lag relationship exists AND the target page exists** - sub-threshold chain members and non-finding concepts render as plain text, never as dead links, and never add co-occurrence links; (2) **every leader-evidence block carries a timestamped citation** (video + `&t=`); (3) **small-sample dossiers carry the same honesty warning as the report/viz**; (4) frontmatter stamps (`type`, `creator`/`concept`, `first_covered`) on every page for Obsidian Bases. `_wiki/` is a corpus output folder like `_briefings/` and `_reports/` - `load_seen_video_ids` must never read it, and the generator never writes to the repo. One generator, not a framework (#95 guardrail); regeneration/refresh discipline is deliberately out of scope for v0. The generator also emits a static `README.md` (via `_readme()`, no PROSE slots) into the vault so the Obsidian how-to travels with the wiki; the companion `scripts/register_obsidian_vault.py` (cross-platform, dependency-free) registers a folder as an Obsidian vault by editing Obsidian's own `obsidian.json` registry (the in-app "Change vault" only filters known vaults and cannot add one) - it refuses to run while Obsidian is open (Obsidian rewrites the registry on exit), writes the registry atomically (temp file + `os.replace`), exits cleanly on malformed JSON, and normalizes paths so an equivalent path never double-registers (the vault id is a stable sha1 of the normalized path). Test contract: `tests/test_register_obsidian_vault.py`. **User-facing home for the whole intelligence layer is the single lecture `docs/intelligence-layer.md`** (mental model + the numbered questions + how-not-to-fool-yourself); the README's intelligence section is a slim invitation pointing there, and `docs/intelligence-layer-environment-setup.md` is archived (retired Neo4j graph lens only). The vault's own emitted `README.md` carries the wandering guide. Reviewers: keep the learning path consolidated in `docs/intelligence-layer.md` - do not re-scatter it back into README sections or per-lens docs. Test contract: `tests/test_wiki_atlas.py` (`test_subthreshold_chain_member_is_plain_text_not_wikilink`, `test_small_sample_dossier_carries_honesty_language`, `test_readme_is_self_contained_reader_guide`).

**Standalone utility:** `scripts/wiki_concepts.py` - the top-N stable-concept wiki generator (issue #148, ADR-0017 Stage 3 / intelligence-layer roadmap Phase 4). Emits one page per top-N taxonomy concept plus a `concept-pages.md` Map of Content into `<corpus>/_wiki/concept-pages` (or an explicit `--out`), companion to `wiki_atlas.py` but a different generator over a different data source: `taxonomy.json` (canonical label + aliases) joined against every video's `concepts.json` (membership) and `meta.json` (identity), plus `mindmap.md` (timestamps) for evidence links - never Gemini, never an embedding, never a database. No `video_intel.py` subcommand was added; it stays a standalone CLI script (`--corpus`, `--out`, `--top`), which is a deliberate scope choice that also sidesteps the `CONFIG_BACKUP_COMMANDS` classification question in `tests/test_config_backup.py` entirely, since that test only parses `video_intel.main`'s dispatch table. The default output directory and the MOC basename were both chosen to never collide with `wiki_atlas.py`'s own `_wiki/concepts/` output (issue #150 P1) - the default was originally the SAME `_wiki/concepts` directory `wiki_atlas.py` writes `concepts/<slug>.md` into, which meant a default run of either generator could silently overwrite the other's pages. `write_pages` also carries defense-in-depth for any future or misconfigured overlap: it reads a page's frontmatter `generator:` value before overwriting it and refuses (`SystemExit`, nothing written) when that value is present and belongs to a different generator, and its stale-page pruning only ever deletes files stamped with its own `GENERATOR_NAME` - foreign and generator-absent files are never touched. Eight invariants reviewers must protect: (1) **selection is video-count rank filtered by cross-channel stability** (`select_stable_concepts`: `>= 3` distinct channels, tie-broken on concept_id for determinism) - a single creator's pet vocabulary must never claim a page regardless of how many of that creator's own videos mention it, and channel membership is deduped by `video_id` first so a title-rotation duplicate filed under two channel folders cannot spoof cross-channel stability; (2) **concept membership is joined from the concepts.json files actually on disk, never from `taxonomy.json`'s own `video_count`** - that field reflects the concept's full corpus history and can be far larger than what a given `--corpus` run can see, so trusting it would silently overcount; (3) **sibling artifacts (`meta.json`, `mindmap.md`) are found by walking the directory and matching a literal `startswith` prefix** (`sibling_artifacts`), never a `Path.glob(f"{prefix}.*")` (a prefix containing `[`, `]`, `*`, or `?` - a bracketed video title - would be misread as glob syntax and lose real siblings) and never by reconstructing a prefix from title/date parts - the PR #136 checker-uses-writer-path lesson applies here too; (4) **a citation never fabricates a timestamp**: `find_timestamp` matches a concept's `branch`/`as_mentioned` against the video's own parsed mindmap headings/bullets and returns `None` on no match; the `as_mentioned` fallback requires a punctuation-aware whole-token match (mirroring `video_intel.py`'s `_alias_boundary_pattern`) plus a minimum 4-char normalized length before it may fire at all, so a short phrase like "AI" can never anchor to an unrelated bullet via substring luck ("m-AI-ntain"); `mention_link` falls back to the plain video URL rather than inventing a `&t=` value; (5) **cross-page wikilinks (`Related concepts`) are restricted to the selected concept set** (`build_co_occurrence` is scoped to `selected_ids` and deduped by `video_id`, so a title-rotation duplicate cannot inflate a co-occurrence count), so every `[[link]]` the generator emits resolves to a page generated in the same run - zero dead links; (6) **creator-authored text (video titles, `as_mentioned`/`branch` phrases) is escaped before interpolation into a table row or `[text](url)` link** (`_escape_md_table_cell`: `|`, `[`, `]`) so a title containing those characters cannot corrupt the row or the link; (7) **`--top` must be `>= 1`** (`parser.error` on 0 or negative) - `select_stable_concepts`'s `scored[:top_n]` slicing silently does the wrong thing for a negative value; (8) **`generated_from` in frontmatter stores only `corpus.name`, never the absolute path** - the absolute path would embed a username/drive letter and make byte-identical regeneration depend on where the corpus happens to be mounted on a given machine, not just its content. Fully deterministic: no wall-clock stamp anywhere in the output; identical inputs and CLI args reproduce byte-identical pages. Test contract: `tests/test_wiki_concepts.py`.

**Standalone utility:** `scripts/atlas_build.py` - the corpus catalog generator (issue #260), plus the shared reader module `scripts/corpus_walk.py` it stands on. Writes ONE derived file, `<output_dir>/_atlas/atlas.json`: one row per `video_id` with facets, a headings-only synopsis, labeled deep links, transcript quality and the already-seen signals (briefing membership, wiki page keys). Not the Creator Atlas wiki (`wiki_atlas.py`, `_wiki/`): the two share a word and nothing else, which is why the skill routes this one as "catalog". User-facing page: `docs/atlas.md`; row contract: `schemas/atlas.schema.json`. Ten invariants reviewers must protect: (1) **no transcript file is ever opened** - transcript presence is a directory-listing fact from `corpus_walk.channel_sibling_index`, and transcript text never reaches any output (`TestSynopsisAndTranscript::test_transcript_file_is_never_opened` spies on `open`); the row's `transcript_source` is read from meta.json only, the stored string verbatim or null, never inferred from the transcript file; (2) **no fabricated URL or timestamp** - the row `url` is the stored `video_url` when it is a well-formed `https` URL and JSON `null` otherwise, never a URL built from an id, and every deep link goes through `timestamp_utils.youtube_deep_link`; a branch with no qualifying leaf gets no link rather than a guessed second; (3) **one walker** [core: one-definition]: `corpus_walk.iter_meta_records` is the only meta walk behind `briefings --unseen`, `topics-build` (both through `video_intel.collect_corpus_videos`, now a projection over it) and the catalog, with the two-artifact winner rule (more mindmap-plus-concepts siblings wins) and a tie kept by the FIRST record in sorted (channel, filename) order; a second walker, or a winner rule that counts transcripts or sidecars, changes which title briefings show; (4) **parsing is shared, deep-link SELECTION is per surface, on purpose** - all three surfaces parse through `wiki_concepts.parse_mindmap_timestamps`, but briefings select with `video_intel.extract_mindmap_links`, concept pages with `wiki_concepts.find_timestamp`, and the catalog with its own R7 rule (`atlas_build.deep_links`: at most three, one per branch, distinct seconds, past-duration leaves skipped); they answer different questions, so a diff that "unifies" them is a behavior change on two surfaces, not a cleanup; (5) **`timestamp_utils.youtube_deep_link`'s rule (scheme `https`, a host in `YOUTUBE_DEEP_LINK_HOSTS`, AND a video id of exactly eleven `[A-Za-z0-9_-]` characters) is deliberately narrower than `video_intel._YOUTUBE_HOSTS`**, which is a channel-shape check on config URLs (host membership only, no scheme or id check); the two host sets happen to hold the same names today, and they must still not be merged or made to share one helper, because the loose check would put a `&t=` on a recovered non-YouTube id filed under a youtube.com URL (a Goldcast-style `goldcast-ab12cd34`); (6) **`generated_at` is never the wall clock** - it is `--generated-at` verbatim, else the newest parseable `processed` stamp in UTC, else the newest `published` date, else null, so an unchanged corpus rebuilds byte-identical and the Drive mount sees no sync diff (`TestDeterminism::test_module_never_reads_the_wall_clock`); (7) **single-file ownership through the `generator` header**, fail-closed like `wiki_concepts.write_pages`: an existing `atlas.json` is replaced only when its `generator` is exactly `atlas_build.py`, and an unreadable file, a non-object or a missing key is refused before the walk (the ownership read uses `MAX_ATLAS_BYTES`, never the 4 MB per-meta default, which refused the real 6.1 MB catalog); the write goes through `atlas.json.<pid>.tmp` and one `os.replace`; the start-of-run sweep removes only a matching temp older than `STALE_TEMP_MIN_AGE_SECONDS` (a younger one may be a concurrent build's live write) and never raises on a listing or unlink failure, and `_file_age_seconds` is the module's one clock read, which never reaches the output; a channel folder the walker cannot list (`WalkResult.unlistable_channels`) stops the write with exit 2 and a counts-only `unlistable=N` line, because its metas are in no counter and the partition would still balance with the channel missing (`TestUnlistableChannel`); (8) **`_atlas/` never holds a file ending `.meta.json`, `.concepts.json`, `.mindmap.md` or `.transcript.md`** - the underscore-prefix rule keeps `collect_corpus_videos` out of it, but `build_taxonomy`'s `rglob("*.concepts.json")` and the `glob("*/*.meta.json")` call sites in `video_intel` stay safe only because of this (`TestCli::test_output_file_set_is_only_atlas_json`); (9) **the catalog is complete by design** - the owner is the sole user, so every record the walker finds is a row, with no filtering by audience, access or source type; a copy of `_atlas/` is a copy of everything, and the sharing layer (policy, projection, export folder) is issue #262, not a flag to add here; (10) **reading never writes** [core: #124 read-guard]: the reader-side `corpus_walk.read_json_best_effort` catches `(ValueError, OSError)`, requires a JSON object, and skips and counts an unusable file; it NEVER quarantines, which is the writer-side `_read_meta_best_effort`'s job and must stay in `video_intel` (`TestReadingNeverWrites::test_corpus_tree_is_byte_identical_after_build`). Sibling discovery is one directory listing per channel folder matched by literal prefix, never a rebuilt prefix and never a glob [core: writer's-path]. `corpus_walk.py` is stdlib-only at import and `video_intel` re-exports every moved name as the same object; PyYAML loads inside `parse_front_matter` only, never on import. Guard tests drive the real `build_rows` or `main` over a synthetic fixture tree, never a stub that agrees with its own assertion, and the summary-line partition `metas == rows + duplicates + skipped + no_id` is asserted on the caller's stdout (`TestCli::test_partition_holds_with_duplicates_and_no_id`) [core: real-caller]; a new guard is falsified before it ships. One generator, not a framework (#95 guardrail); no Gemini, no network. Test contract: `tests/test_atlas_build.py`, `tests/test_corpus_walk.py` (`TestMovedNamesAreOneObject`, `TestIterMetaRecords`, `TestCollectCorpusVideosIsAProjection`), `tests/test_timestamp_utils.py::TestStandaloneScriptImportIsolation`.

**Standalone utility:** `scripts/atlas_render.py` - the catalog page renderer (issue #261), the one consumer of `_atlas/atlas.json` that ships with the repo. Reads the atlas and the template beside it (`scripts/atlas_catalog_template.html`), never the corpus, and writes ONE file, `catalog.html` next to the atlas (or `--out`): three views over one cross-filtered set (Cards, Compact, Grid), a facet rail, prefix search, a bookmarkable URL hash, light and dark. The page is private like the atlas it embeds. Six invariants reviewers must protect: (1) **self-contained** - the page loads no script, style or font from the network, and the template keeps exactly ONE `https://` string outside the data block, the YouTube thumbnail host; thumbnails are the one deliberate outbound fetch, built in the page from each row's own stored watch URL (never from `video_id`), lazy, `referrerpolicy="no-referrer"`, and switchable off (`TestSelfContained`); (2) **the data block is unicode-escaped** - every `<`, `>` and `&` in the embedded JSON becomes `\u003c`, `\u003e`, `\u0026`, not just `</`, because a title holding `<!--` plus `<script` would otherwise put the HTML tokenizer into the double-escaped script state and swallow the page's real closing tag (the `lead_lag_viz.render_html` rule); and corpus text reaches the DOM only through `textContent` and `setAttribute`, never `innerHTML` (`TestEscaping`); (3) **the template sentinel appears exactly once and the data is joined by splitting on it**, never `str.replace` on the output, so corpus text is never re-scanned for the sentinel; (4) **ownership by marker, fail-closed** like `atlas_build.check_ownership` - an existing output is replaced only when its head carries `<meta name="generator" content="atlas_render.py">`; a hand-written page, an unreadable file or any other generator's page is refused with exit 2 and left byte-identical, and the write goes through `catalog.html.<pid>.tmp` plus one `os.replace` (`TestOwnership`); (5) **the renderer never fabricates a link** - deep links, URLs and timestamps come from the atlas rows as written by `atlas_build` (which already routes them through `timestamp_utils.youtube_deep_link`), and the page renders a non-`https` URL as plain text; (6) **input is checked before any write** - the file must be an `atlas_build.py` atlas at `schema_version` 1 with a rows list, else exit 2 and nothing written (`TestInputGuards`); a failed write (a read-only folder, a refused `os.replace`) reports the same way, never as a traceback, and the temp never survives (`TestOwnership`); (7) **the page script has an executable guard, not only a text one** - `node --check` over the inline script (`TestPageScript`) and a headless-Chromium smoke over a synthetic atlas (`tests/test_atlas_render_browser.py`: hostile title lands as text, a facet click in Compact keeps the Compact page size, two headings with one cleaned label keep their own deep-link seconds, the hash restores a view), each skipped when its tool is absent, because the pytest text checks alone let a JavaScript syntax error ship green; (8) **one page-size rule** - every reset of `state.n` goes through `pageSize()`, so a facet click in Compact never collapses the table to the Cards page size; a pending search debounce is cancelled by `fromLocation` and by Clear all, so a stale timer cannot re-commit a query after back/forward; deep links are consumed in document order with a cursor, never through a label-keyed map; and the template's transcript-quality list is pinned to the schema enum (`TestVocabulary`). The rail carries a Concept facet (every selected concept required, top 15 with a filter box, zero-count values hidden like the quality facet's); transcript-quality values are DISPLAYED as plain words (`none` as "no transcript", `unknown` as "not assessed") while the data values never change. A Transcript source facet (hash key `ts`, values from the row's `transcript_source`, else `none` for a `none`/`skipped` quality, else `unrecorded`, all through one `rowSource` rule) and a muted "captions" badge on caption-sourced rows exist; Gemini stays silent like `complete`, and the source facet is hidden when no row carries the field, so an older atlas shows no such facet (`TestVocabulary::test_template_source_labels_cover_the_known_values`, `tests/test_atlas_render_browser.py`). Rendering is byte-identical for the same atlas and template (`TestDeterminism`). Stdlib-only at import, in the #152 isolation list; the script-safe escape chain is a deliberate text copy of `lead_lag_viz`'s (that script sits on the report stack), pinned by `TestEscapeChainParity`. Test contract: `tests/test_atlas_render.py`, `tests/test_atlas_render_browser.py`.

**Standalone utility:** `scripts/atlas_export.py` - the public-subset exporter (issue #262), the only thing that may turn the private catalog into a copy that leaves the machine. Reads the private `atlas.json` and a YAML policy, writes `<out>/atlas.json` (`generator: atlas_export.py`) plus `catalog.html` through `atlas_render`, into `_atlas-export/` by default. Eight invariants reviewers must protect: (1) **default deny, four times** - a row survives only when its channel is in the policy's explicit allowlist, its date is on or after `since`, its `url` equals the canonical `https://www.youtube.com/watch?v=<its own id>` (other platforms never qualify), its id is not in `exclude_video_ids`, AND the YouTube Data API reports it `public` (`fetch_privacy_status`, `videos.list part=status` in batches of 50; an unlisted video, a deleted one, and a local ingest filed under an id-shaped id are all absent from the API's answer or not `public`, and are dropped and named on stderr); a kept row is projected onto `PUBLIC_ROW_KEYS` (an ALLOWLIST of fields, never a drop list, so a field added to the private row later is absent from the public one by construction); the concept map and channel counts are rebuilt from the kept rows and `topics` is always empty; the export header never carries the private corpus size. **The visibility check is the one that bit**: the first real export committed 27 unlisted videos behind canonical URLs, found by the security reviewer measuring every committed id against the API, so a diff that makes the check optional by default, or silently skips it when the key is missing, reopens exactly that; `--no-verify-public` is the explicit, warned opt-out and a missing `YOUTUBE_API_KEY` is a refusal; (1b) **a policy channel with no exportable video is a refusal** (`unmatched_channels`), so an allowlist typo cannot export silently; (2) **a deep link survives only as the row's own canonical URL plus `&t=<seconds>`** (a link to any other video is dropped); (3) **the policy is refused, never defaulted** - unknown keys, duplicate keys, non-string keys, a non-list or empty `channels`, a malformed `since`, a non-id in `exclude_video_ids`, each exits 2 with nothing written; the loader is a `yaml.SafeLoader` subclass whose only addition is those refusals; (4) **`--deny-terms` scans the serialized subset BEFORE any write** and aborts on a hit (the owner's private term list; a public title can trip it, and the remedy is `exclude_video_ids` or a demo copy of the list, decided by the owner, never by the script); (5) **the private folder is never the destination, and nothing another tool wrote is ever removed** - `--out` resolving to the atlas's own folder is refused, an `atlas.json` not written by `atlas_export.py` or a `catalog.html` without the renderer's marker in `--out` is refused BEFORE any write (through `atlas_render.check_ownership`, one definition), and a failed render removes only what this run wrote (the page is unlinked only when it did not exist beforehand; the first cut deleted a hand-written page the renderer had just refused, caught by four reviewers); (6) **the input must be the private atlas** (`generator: atlas_build.py`); re-exporting an export is refused; (7) **byte-stable** for the same atlas and policy, with the policy's sha256 prefix, channel list and date floor recorded in the `export` header. The guard tests are canary-based: the synthetic private atlas carries a canary string in EVERY field of every denied row (title, headings, aliases, topics, wiki keys, concept labels, the other folder of a duplicate), and `TestCanaries` asserts no canary byte reaches either output file [core: real-caller]. `examples/catalog/` holds one real exported bundle plus the policy that produced it; it is regenerated by the same command, never edited by hand, and `tests/test_catalog_demo.py` makes that mechanical: every committed row obeys the committed policy and `PUBLIC_ROW_KEYS`, the side tables match the rows, the page re-renders byte-identical from the JSON beside it, and (when the owner's private term list is on the machine) no term appears in any committed byte. An excluded id in that committed policy is itself public. `atlas_render.load_atlas` accepts exactly `ATLAS_GENERATORS` (`atlas_build.py`, `atlas_export.py`), nothing else, and the page ignores a URL hash that names a facet the rail does not show. Stdlib-only at import (PyYAML inside `load_policy`, `urllib` inside `fetch_privacy_status`), in the #152 isolation list. Test contract: `tests/test_atlas_export.py` (the status request is the one stubbed boundary), `tests/test_catalog_demo.py`.

**Import weight is a contract for this whole layer (issue #152).** These scripts are standalone, read-only analytics: none of them should require the curate stack to import. `timestamped_url` therefore lives in `scripts/timestamp_utils.py` (stdlib-only, no dependencies) and every consumer here imports it from there. `intel_graph.py` keeps a re-export so `tests/test_intel_graph.py` and any external caller still resolve `intel_graph.timestamped_url`, but importing it FROM `intel_graph` re-couples the importer to `video_intel` and thus to a module-level `googleapiclient` import. Before #152 that chain meant `wiki_concepts`, `wiki_atlas`, `lead_lag_report`, `lead_lag_viz`, and `burst_report` all failed to import outright when `google-api-python-client` was absent, and the two lazy-import workarounds in `wiki_atlas.py` and `wiki_concepts.py` bought nothing, because each module already paid the full cost through a module-level import elsewhere in the same file (`wiki_concepts` directly via `from intel_graph import timestamped_url`, `wiki_atlas` transitively via `lead_lag_report`). Reviewers: a new `from intel_graph import timestamped_url` in any of these scripts needs pushback. Test contract: `tests/test_timestamp_utils.py::TestStandaloneScriptImportIsolation`.

Deliberate divergence, not an inconsistency: `wiki_atlas.py` bans co-occurrence links entirely (only a validated lead-lag relationship earns a wikilink), while `wiki_concepts.py` authorizes co-occurrence links but restricts them to its own selected top-N concept set (`build_co_occurrence`, scoped to `selected_ids`). The two generators answer different evidence questions - lead-lag adoption order versus corpus-wide concept stability - and each cross-link policy is the correct one for its own evidence contract.
